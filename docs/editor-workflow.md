# Editor: scene integration, editing and samples

**Requirement, added 27 October 2026:** Editor receives Film's brief and Mark's written scene handoff, integrates supported assets into Remotion, and delivers one representative rendered frame per story scene for each selected deliverable. Use `.codex/agents/editor.toml`. Configuration defines a role; it does not install an automatic runner, invoke other agents or authorize messaging other chats.

## Ownership

| Owner | Contract |
| --- | --- |
| Film | Medium/compositing, visual intent, coordinate/physical baseline, projection and camera strategy |
| Mark | Written scene sheets/index with numeric staging, named spaces/anchors, acting, camera paths, light, cut intent, integer event frames and acceptance criteria |
| Boss | Reusable assets/rigs/props/sets, coordinate conversion, shared renderer/camera/effect/transition capabilities, contracts/validators and fixes in their owning modules |
| Editor | Scene/timeline authoring and assembly, supported asset selection/staging/timing, narration/amplitude/subtitle/SFX integration, supported effects/transitions/endings, rendered samples and sequence/runtime QA |

Editor reads the exported API/source and authors supported values. Missing reusable behavior or asset/contact defects go to Boss with shot/frame evidence and consumers. Keep geometry/SVG/rigs, projection and shared timing/transition algorithms in their owning library modules. Editor may implement a shared change only when explicitly assigned that scope, following Boss's workflow. Preserve unrelated work.

## Steps and completion criteria

1. **Establish inputs and scope:** read AGENTS.md, [delivery record](delivery-workflow.md), script/fact-check, Film brief, [Mark handoff](mark-storyboard-workflow.md), index/neighbors, [editing principles](editor-principles.md) and relevant [dev findings](dev-findings.md). Record matching revisions and selected deliverables. Complete when timing, constraints, source status and open questions are explicit.
2. **Preflight capabilities:** follow [Remotion toolkit](remotion-toolkit.md) package/version/API checks; inspect Root, types, validator, registries, renderer and helpers. Label required elements existing-integrated / exists-unintegrated / missing / unknown, with paths/commit. Complete when supported scene inputs and Boss-owned gaps/dependencies are known; document fields are not automatically JSON fields.
3. **Assemble the sequence blockout:** follow [sequence workflow](sequence-workflow.md); retain one deterministic executable assembly per selected deliverable. Use representative shared placeholders, physical dimensions/anchors and explicit seekable entry/exit states. Preserve script timing, claims/clues and reveal frames; map story scenes/shots to runtime indices and composition frames. Complete when Film/Mark can review the assigned continuous sequence before polish; unavailable neighbors/placeholders remain unverified.
4. **Integrate and edit:** use library IDs and declared coordinate/clock conventions for staging, camera keys, light changes, narration, amplitude, Thai cues and licensed SFX. Apply [editing principles](editor-principles.md) to rhythm, information flow and transitions. A transition records its purpose, frame range, overlap/duration treatment, audio/subtitle owner and supported implementation. Changes to story/claims go to Preaw/Boat, visual approach to Film, shot intent to Mark, shared APIs to Boss. Complete when the executable timeline matches the agreed handoff and source revisions.
5. **Validate actual picture/time:** complete [Boss's authoritative visual/runtime QA](boss-asset-workflow.md#visual-and-runtime-qa-before-push) for all selected/affected compositions. Editor owns execution of that checklist for scene integration; Boss owns it for shared-library changes and affected consumers. This includes Studio, seeking, renders, one-second/final-frame contact sheets, event/cut adjacent frames, continuity, scale/contact, Thai readability and audio/reveal checks. Complete when results and limitations are recorded without treating a still as a motion/sequence pass.
6. **Send scene samples:** follow the contract below after blockout or an integration revision is ready to review. Complete when every assigned story scene has an inspected representative frame, or an explicitly reported rendering blocker and next owner. Present available samples even if other scenes are blocked; do not fabricate replacements or mark unavailable images complete.
7. **Deliver:** follow [contribution workflow](contributing.md). Report source/handoff/runtime revisions, selected timeline/composition/input props, mapping, implemented assets/capabilities, actual QA, sample paths, findings and remaining limitations. Update index/delivery status separately for planning, runtime, audio, user approval and release readiness.

## Scene samples for the user

The user-facing review set is **one representative frame per story scene per selected deliverable**. A scene containing several runtime entries still needs one scene sample, not one image per array entry. A scene present in two selected editorial versions needs a sample from each version's own composition/timing. An unselected alternate aspect ratio is outside sample scope unless explicitly requested or affected-consumer QA requires it.

- Choose the scene's main action, clear composition or meaningful reveal, following Mark's proposed key frame where useful. Use an actual Remotion still at native output size from the selected timeline and current revision. Avoid a black ending, incidental dissolve/flash or placeholder-only frame that conceals unfinished staging; label unavoidable placeholders and choose a representative visible state.
- Record `deliverable ID`, story scene/shot/key-state ID, handoff revision, code commit plus working-tree status, timeline/input props, composition ID/dimensions, composition-global frame and scene/shot-local frame, sample path, purpose and limitations. Audio/caption media revisions are recorded when present. The index links this manifest without duplicating every shot sheet.
- Store images and manifest under ignored `out/samples/<episode>/<deliverable>/<revision>/`; use stable scene IDs in filenames. Record reproduction command/inputs so another checkout can regenerate local-only media. Commit written evidence/links, keep generated images outside Git under existing policy.
- Open and inspect each actual sample for missing assets, focal action, contact, crop, light/color and Thai glyph/safe-region problems. Fix or flag defects before sending it. Embed the images in the user-facing message with absolute local paths and concise Thai scene/frame captions where supported; a path list alone is insufficient when images can be displayed. For many scenes, send all scene images in batches or an overview contact sheet with accessible individual stills and manifest; every scene must be represented.
- Label `blockout sample`, `integration sample` or `polish sample` and note material unfinished elements. Refresh samples of changed scenes; reuse unchanged samples only when their source revision and inputs still apply. A sample is a review aid, not implicit user approval, pacing/audio verification or a substitute for full motion/continuity QA.

This workflow change does not itself request a new render of an existing episode or establish an automated sample exporter. Use the existing still-render route after checking its actual API, or request a missing shared capability from Boss. A production assignment includes this sample delivery; instruction-only work uses the documentation verification exception.
