# Coordinator duties and agent parity

**Status:** moved here from [AGENTS.md](../AGENTS.md#coordinator-and-agent-parity) on 11 Nov 2026 so role agents no longer load it on every invocation. Rule levels are unchanged. **Read when:** you are the coordinator (before coordinating a deliverable or invoking a role) or you edit a role config.


The **coordinator** is the chat session the user talks to (Claude Code, Codex or Cursor). It does the following:

- selects deliverables, style profile and tier;
- invokes role agents for the assigned scope through Claude Code's `Agent` tool (`subagent_type: <role>`), Codex's `spawn_agent` (`agent_type: <role>`) or Cursor's `Task` tool (`subagent_type: <role>`);
- passes matching revisions;
- publishes the [user storyboard review page](../.agents/skills/review-page/SKILL.md) whenever Film returns a `ready-for-dev` scene-sheet revision or Film adds look frames, built with `scripts/storyboard-page/build.py` from Film's `review-rows.json`, and relays the verdicts back;
- follows the [agent invocation defaults](#agent-invocation): whole stage per call (shot groups for painting and rendering), inline mechanical edits, separate checking.

<a id="coordinator-duties"></a>
**Coordinator duties kept in other documents** (user, 7 Nov 2026). Each rule lives in the linked document; read that section when its moment comes:

- **Start and pick:** create `delivery.md` and `task.md` ([delivery record](delivery-workflow.md#delivery-record-and-handoff-checks), [task file](delivery-workflow.md#task-file)); have the user pick a concept ([ideation](delivery-workflow.md#ideation)); propose the open deliverable closest to W8 first ([finish first](#wip-limit)).
- **User rounds:** ask the user in four rounds and take the recommended option between them ([fast lane](delivery-workflow.md#fast-lane)); bring deliverables at the same round into one sitting.
- **Before the user sees pictures:** run the [viewer check](sequence-workflow.md#viewer-check); voice takes for choosing are at most 10 s ([audition cap](delivery-workflow.md#voice-audition-cap)).
- **Review page:** batch ready shots into one [review round](#review-rounds) (no daily cap); record the page URL in `delivery.md` in the same turn; read verdicts, render the next [stage](render-rules.md#render-stage) and pin passed finals with `pin.mjs` ([moving a shot on](sequence-workflow.md#painted-shot-by-shot), W7).
- **Cover and title:** when the draft cut passes (R3), invoke the Cover role for pick 1, then for pick 2 once the picture is chosen ([cover pass](#cover-pass)); W8.2 stays closed until task step W6c is ticked.
- **Publish and post:** after a delivery render or a cover pick or fix, run `store.py publish` and give the user `publish/<channel>/<PROJECT>/<ID>/` (W8.2); when the user says it is posted, `store.py publish <ID> --posted <date>` (W8.3) ([publish folder](../README.md#publish-folder)).
- **Fix rounds:** one `fixlist.md` per round ([AI12](delivery-workflow.md#ai12)); after two fix passes on a shot group the user decides ([fix-pass cap](boss-asset-workflow.md#latest-production-rules)).
- **Rules and repo:** list `proposed` rule changes for the user at a stage end and apply them in a docs-only PR ([DP03–DP04](contributing.md#tools-and-document-improvements)); tooling waits for the [maintenance window](contributing.md#maintenance-window); check that a PR is unmerged before pushing to its branch ([merged-PR check](contributing.md#merged-pr-check)); a user note repeated on a second episode goes into [user taste](user-taste.md); tick W8.3 when the user says a video is posted.

[Role configs](../AGENTS.md#coordinator-and-agent-parity) install no runner; a role agent never invokes the next role.

`.claude/agents/<role>.md` and `.codex/agents/<role>.toml` must carry the same name, description and instructions. `tests/agents.test.ts` enforces this, so edit both in the same change. Claude front matter also carries a required `tools:` allowlist (Claude-only) that keeps each role's startup context small. Add a tool there before a role depends on it. Optional Claude-only `model:` and `effort:` lines pin a role's model and reasoning effort; a role that needs two models has a child config (`film-apply`, `boss-apply`) whose instructions point to the parent's file instead of copying it; the front matter is the current record and `git log -p .claude/agents/` its history. The coordinator may override them per call. OpenCode copies (`.opencode/agents/<role>.md`) are generated from the Claude files by `python3 -I scripts/opencode-agents.py`, together with `<role>-gpt` twins on the Codex subagent model from `.codex/config.toml` (the default pick in OpenCode, see [native OpenCode role calls](#native-opencode-role-calls)); rerun it after editing a role (the same test checks them). OpenCode reads skills from `.claude/skills` and `.agents/skills` directly and MCP servers from `opencode.json`. ZCode copies (`.zcode/agents/<role>.md`, GLM-5.3) are generated the same way by `python3 -I scripts/zcode-agents.py`; ZCode reads skills from `.agents/skills` and MCP servers from `.agents/mcp.json`, a symlink to `.mcp.json`. Cursor copies (`.cursor/agents/<role>.md`) are generated by `python3 -I scripts/cursor-agents.py`: same name, description and instructions, Claude `model` + `effort` as Cursor `model[effort=…]` (no `tools:` field); Cursor also reads `.claude/agents/` for compatibility, and `.cursor/agents/` wins on a name clash (see [native Cursor role calls](#native-cursor-role-calls)).

## Native Codex role calls

- Start a fresh session in the trusted project to load the role files and [project config](../.codex/config.toml). Use the assigned role name from `.codex/agents/`. For an eligible same-pass follow-up under AI04, send input to that existing agent while the session can still reach it.
- The project defaults native subagents to `gpt-6.2-sol` at `medium`, as set in [AI14](#ai14). Native Codex Film and Boss pin `gpt-6.2-sol` at `medium` in their role TOML files. Use a per-call override for an unpinned role when the user requests one. The Film and Boss Claude model-by-pass rules apply to Claude calls.
- Codex role agents inherit the coordinator's available tools and permissions. Check the [project MCP setup](../README.md#claude-code--codex-setup) when a pass needs a local server. Use the [storyboard publishing instructions](../.agents/skills/review-page/SKILL.md#review-page) for review pages.

<a id="native-opencode-role-calls"></a>
## Native OpenCode role calls

**Default (user, 17 Nov 2026).** In OpenCode, the coordinator runs each role pass on the `<role>-gpt` twin (`gpt-6.1-sol` at `medium`) first.

- **Usage-limit fallback:** when a `-gpt` call stops on an OpenAI usage or rate limit (quota exhausted, 429), start the same brief on the Claude agent `<role>` without asking, and tell the user which role and pass moved. That role stays on Claude until the end of the session. Do not retry the same pass on GPT. A real task failure goes to the user, not to the other provider.

<a id="native-cursor-role-calls"></a>
## Native Cursor role calls

**Default.** Cursor loads root [AGENTS.md](../AGENTS.md) as project instructions (same file Claude Code reaches via [CLAUDE.md](../CLAUDE.md)). Role passes use `.cursor/agents/<role>.md` through the Task tool (`subagent_type: <role>`).

- Edit Claude role files, then rerun `python3 -I scripts/cursor-agents.py` (and the OpenCode/ZCode generators) so every harness stays in sync; `tests/agents.test.ts` checks the copies.
- Model and effort come from each Cursor front matter pin. Override per call when the user asks, and apply the Film and Boss [model-by-pass](#ai14) rules the same way as on Claude.
- Cursor reads project skills from `.agents/skills` / `.claude/skills` and MCP servers from `.mcp.json` (or a `.cursor/mcp.json` link when present).
- **Claude calls** use the model in the agent's front matter; the Film and Boss model-by-pass rules ([Film](#film-model-by-pass), [Boss](#boss-model-by-pass)) name which agent (`film` or `film-apply`, `boss` or `boss-apply`) takes a pass.
- **User choice wins:** when the user names a provider or model for a pass, use it.

<a id="resolve-the-selection"></a>
## Resolve the selection before writing

Moved from [delivery-workflow](delivery-workflow.md#resolve-the-selection-before-writing) on 11 Nov 2026.


1. Read the user's request and the existing episode delivery record. Reuse an explicit selection; do not ask again when the user already chose the formats or supplied a scoped revision request.
2. For a new video, run the [ideation round](delivery-workflow.md#ideation) first; the chosen concept settles the genre, medium and tone it names. If the selection or a [style profile](delivery-workflow.md#style-profile) field the concept leaves open is missing or materially ambiguous, ask with the harness's structured-question tool: `AskUserQuestion` in Claude Code, `request_user_input_async` in Codex; if neither exists, ask in chat. Ask only for what the prompt leaves open, in one call in the user's language: the **selection** with three choices, **both**, **Short only**, **Long only**, showing the duration targets from production requirements (Thai example: “หัวข้อนี้ต้องการทำทั้ง Shorts และ YouTube แบบยาว หรือเลือกแบบใดแบบหนึ่ง?”), the **style** (genre/medium, voice, music) and the **target length** when none is stated or implied, and whether the user has a **look reference** (image, link or earlier episode) when the medium is illustrated or 3D. For an animated or illustrated deliverable, the same call also asks the [visual engine](delivery-workflow.md#visual-engine) unless the prompt or record names one. Do not ask about a choice the prompt or the delivery record already settles. A sent question, preselected option or elapsed wait is not an answer. Continue independent research while waiting; begin format-dependent writing/scene sheets only after the selection is resolved.
3. Record the answer or existing instruction in `scripts/<episode>/delivery.md`: selection, style profile and pipeline (`Full`), evidence of the user's choice, deliverable IDs, target durations and scope. `short`, `long` and `both` are authoring labels, not runtime fields. Default counts are one standalone Short and one Long when both are selected. A chapter series, multiple Shorts or additional edits require explicit scope; selecting both does not make every Long chapter a Short.
4. Create `scripts/<episode>/task.md` ([task file](delivery-workflow.md#task-file)) and route each selected deliverable through the [pipeline](delivery-workflow.md#pipeline-tiers): Ideation → Boat research → [hook pick](delivery-workflow.md#hook-pick) (Preaw options, the coordinator asks the user) → Preaw script → Boat fact-check → Film brief and written scene sheets → Boss shared assets/capabilities → Editor integration/editing. Shared research may feed both. A scriptwriting-only assignment ends with editorial handoff; selection does not authorize automatic downstream production, agent execution or cross-chat messaging.

Selection is complete when the record identifies the selected deliverables and the instruction resolving the choice. An explicit custom duration/scope overrides defaults with its reason recorded. For a new version of existing production, preserve existing IDs and evidence; record a migration map before changing paths or IDs. Workflow updates alone do not migrate historical episodes.

## Finish first


**Default (user, 3 Nov 2026):** any number of deliverables may stay open; none is parked. When the coordinator proposes what to work on next, or the user asks, it proposes the open deliverable closest to W8 first, and its next-step questions name that one. A deliverable waiting on the user is listed with the one decision it waits on. Evidence: on 3 Nov 2026 eight deliverables were open at once while six had been posted.

<a id="agent-invocation"></a>
## Agent invocation (coordinator rules)

**Default** for how the [coordinator](coordinator.md#coordinator-and-agent-parity) runs a tier's stages. Every role agent starts cold and rereads AGENTS.md and its core documents, so invocations cost context. A brief may override a rule with a recorded reason.

The rules that bind a role agent inside its own run (AI09, AI10, AI11, AI13) stay in [delivery-workflow](delivery-workflow.md#agent-invocation).

- **AI01 — One invocation per stage and revision.** Send the whole stage scope in one brief (every beat, shot or asset it covers), not one call per shot or fix. Batch review notes for the same owner into one revision. **Exception for painting and rendering stages:** Boss and Editor plate work, and Film spikes that paint or render, go one invocation per shot group of 3–5 shots (or one asset family). The delivery record lists the remaining groups. Cost grows with turns × accumulated context, and whole-stage runs measured 150–170 turns at 500–580k peak context (ZCPAINT, 30 Oct 2026).
- **AI02 — Coordinator does mechanical edits inline.** Small edits with no judgment call do not need a role agent: a value, typo, link or `Stage / Next owner` update, applying a change the owning role already decided and recorded, a [single-value fact-check correction](editorial-workflow.md#inline-fact-fixes), or reading status. Name the owning role in the change (e.g. "coordinator for Film, SS-R2.5"). New or substantially revised scripts, fact-checks, briefs, scene sheets, assets and Blender/render work always go to the owning role.
- **AI03 — Keep authoring and checking separate.** The role that checks a piece of work never runs in the same invocation as the one that wrote it (Boat's fact-check of Preaw's script). Boss and Editor runtime work (Blender, renders, audio generation) runs in their own agent, so logs and frames stay out of the coordinator's context.
- **AI04 — Fresh invocation per pass.** Each pass of a role (a new revision, a review-and-fix round, the next shot group) starts a fresh invocation with a short brief: inputs by path and revision, the decisions made since the last pass and the delta to do. Do not resume one agent across passes: its context and cost grow with every pass (BLOOP-EP01-SHORT, 30 Oct 2026: Boss ran 7 passes in one context, 466 calls, 40 % of the session's tokens). Continue an agent (Claude Code: `SendMessage`) for a clarification of the pass it just finished, or for a follow-up fix on the same shots when that pass ended under about 60 calls and less than an hour ago (its files are still in its warm cache, so a fresh invocation would only pay to reread them). **Check this first (Requirement; usage review, 16 Nov 2026):** before starting a fresh invocation for a fix, the coordinator checks whether such an agent exists and continues it when it does. A fresh run costs its startup context plus rereading the same files (measured 1–15 Nov 2026: startup context is 46 % of input-side cost; a Boss or Film Opus run averages $3.40–6.50).
- **AI05 — Point, don't paste.** Briefs name file paths, revisions and stable IDs. They do not paste document or handoff content into the brief, and they list only the trigger documents the stage needs beyond the role's core reads.
- **AI06 — Wait once for long jobs.** Batch renders and Blender jobs into one run and wait for it once (a background job or `Monitor`), not with repeated polling. Prove the shot with sampled frames or a low-resolution pass before a full render. A run longer than about 10 minutes renders in per-shot chunks, so a stop resumes at the next chunk, and writes progress (chunks or frames done of total, elapsed, estimate) to its log under `out/logs/`; the coordinator answers status questions from that log's last lines. [AI10](delivery-workflow.md#ai10) covers who waits.
- **AI07 — Short sessions, handoff through the record.** A coordinator session covers one stage, or one review-and-fix round, for one deliverable. Before the session ends, the delivery record's `Stage / Next owner` cell, the [task file](delivery-workflow.md#task-file) and the handoff files carry everything the next step needs (revisions, open items, evidence paths). The next session starts from `task.md`, `delivery.md` and the named revisions, not from chat history. Start a new session rather than continuing one whose context is already long. Keep the model fixed within a session, because switching models restarts the prompt cache.
- **AI08 — One correction, one pass.** When a user correction touches several handoff files (a prop state, a hand side, a mirrored camera), the coordinator invokes once the role whose judgment the correction needs. That invocation updates every affected file (brief, scene sheets, index) with a change-log line naming each file's owner; the other owners review it in their next scheduled pass instead of a relay of invocations. Boss or Editor re-runs once, after the files agree.
- <a id="ai12"></a>**AI12 — One fix list, one pass per owner.** User verdicts and critic findings for a review round go into `scripts/<episode>/fixlist.md` (one line each: shot, note, owner, status). The coordinator sends one invocation per owner when the user has finished that round on the page, not one per note as notes arrive; the user can ask for a single note to go now. **One run per owner per round (Requirement; usage review, 16 Nov 2026):** a note that arrives while a fix pass is running is appended to `fixlist.md` for the next round, not sent as another invocation. `fixlist.md` records the round number and each owner's invocation count; a second invocation for the same owner in one round needs a recorded reason (the user's "go now", or an [AI09](delivery-workflow.md#agent-invocation) checkpoint). Notes whose value is already decided skip Film and go to the implementer ([AI13](delivery-workflow.md#ai13)). Measured 1–15 Nov 2026: Film, Boss and Editor averaged 5.7–6.5 runs per branch, and 16–26 % of their runs were named fix or redo passes. Evidence: ZCONDO2 Draft (4 Nov 2026) ran nine single-note Boss and Editor passes in three hours (hands, grip, face height, caption shade).
- <a id="ai14"></a>**AI14 — Model by pass (Default; user, 14 Nov 2026).** A role pass runs on the model in its config (`.claude/agents/<role>.md` frontmatter, `.codex/agents/<role>.toml`) unless the user names another. **Sonnet passes of an Opus role go to a pinned agent, never a per-call override (Requirement; user, 21 Nov 2026):** `cover`, `film-apply` and `boss-apply` below, so the model no longer depends on the coordinator remembering it. Native Codex subagents default to `gpt-6.2-sol` at `medium`. The brief names the model when it differs from the pin.
  - <a id="cover-pass"></a>**Cover pass (Requirement; user, 21 Nov 2026).** The cover and title (the [cover-design skill](../.agents/skills/cover-design/SKILL.md): five pictures, five text versions, five titles) are the Cover role's work: invoke `subagent_type: cover` (`agent_type: cover` in Codex), whose config pins `claude-sonnet-5-5` at `medium`, one invocation for pick 1 and one for pick 2. Never send a cover or title pass to Film, and no per-call model override is needed. The step is `W6c` in the [task file](delivery-workflow.md#task-file), and `ep.py tick` refuses W8.2 while it is open. This replaces the per-call Sonnet override on Film (16 Nov 2026), which was forgotten in practice (user, 21 Nov 2026). The user may name another model per pass.
  - <a id="film-model-by-pass"></a>**Film model by pass (Requirement; user, 21 Nov 2026; a per-call override since 16 Nov 2026).** Every Film pass that applies decisions already made instead of making them goes to the child agent `film-apply` (`subagent_type: film-apply`, pinned `claude-sonnet-5-5` at `medium`), not to `film` with a model override: review rows for the [review page](../.agents/skills/review-page/SKILL.md), re-timing scene sheets after the voice lock, frame checks and QA sheets of finished shots (the [batch check](#boss-batches) included), fix passes whose notes name the change, and the [viewer check](sequence-workflow.md#viewer-check). `film` (`claude-opus-5-5`) keeps the passes where the look is designed or judged: ideation annotation, the visual/technical brief, the first write of the storyboard and scene sheets, look frames, any pass that paints (thumbnails, look frames, and their viewer-check fix rounds), and a fix pass whose note needs a new design. `film-apply` returns such an item as "needs film" instead of deciding it. <a id="film-apply-one-invocation"></a>**One invocation for rows and re-timing (Default; user, 21 Nov 2026):** when the review-rows pass and the scene-sheet re-timing pass after the voice lock are both due, they are one `film-apply` invocation, not two: they read the same scene sheets back to back, so a second fresh invocation only pays to reread them. Unchanged: the viewer check is always a fresh invocation that has not seen the work, and the [cover pass](#cover-pass) stays a separate agent and invocation (different inputs and timing). Measured 1–15 Nov 2026: Film on Opus cost $1,025 over 300 runs ($3.42 a run), Film on Sonnet $57 over 100 runs ($0.57 a run, on lighter passes).
  - <a id="boss-model-by-pass"></a>**Boss model by pass (Requirement; user, 21 Nov 2026; a per-call override since 17 Nov 2026).** These Boss passes go to the child agent `boss-apply` (`subagent_type: boss-apply`, pinned `claude-sonnet-5-5` at `medium`), not to `boss` with a model override: a fix pass whose values are already decided ([AI13](delivery-workflow.md#ai13)), sets and props, the `easy` [batch](#boss-batches), shared renderer work and its tests, and [kit intake](../src/painted/kit/README.md#kit-intake) (W8.4; user, 21 Nov 2026): one `boss-apply` invocation files the episode's outfits, poses, motions, props and sets as copies and returns only a new character or animal comp card as "needs boss"; an episode with nothing new to file needs no `boss` pass. A `boss-apply` fix pass continues the builder through `SendMessage` only under the [AI04](#agent-invocation) condition; otherwise it is a fresh invocation. `boss-apply` returns an out-of-scope item as "needs boss". `boss` (`claude-opus-5-5` at `medium`) keeps movement (walks, leaps, cycles; [Boss owns movement](boss-asset-workflow.md#boss-owns-movement)), a new character or animal, and arm, hand or face work, where Sonnet lost the same-brief test (raptor, 14 Nov 2026). **Per-ticket trial ended (user, 20 Nov 2026):** from 19 Nov 2026 every Boss pass ran on Sonnet, one pass per Film-written plate ticket. On EDU-EP30 (28 shots, to the end of W5.2) Boss took 62 runs, $124 and 21.1 agent-hours and Film $125, against EDU-EP26 (28 shots, same stage) at 5 Boss runs, $39, 1.6 hours and Film $41; 23 of the 62 runs were fix passes and Film ran nine extra decision rounds. Boss builds in the batches below, on the agents above.
  - <a id="runtime-routing"></a>**Runtime routing (Requirement; user, 21 Nov 2026).** The user can send a role to another provider or model without a commit. The switch is one JSON file outside Git, shared by every worktree (`$REELS_ROUTING`, default `~/.config/reels-studio/agent-routing.json`), written with `python3 -I scripts/agent-route.py set <role> <provider> [--model M] [--effort E]` and `clear <role>`; `show` lists every role, and `serve` opens the same switch as a local page (`http://127.0.0.1:8791`; `role-routing` in `.claude/launch.json`) where a change saves at once. A role with no route runs on its pin above. Providers: `claude` (the pinned agent with another model or effort on the Agent call) and `codex` (`codex exec`, default `gpt-6.2-sol` at `medium`); a new provider is one `PROVIDERS` entry in the script. For a role routed to another provider the coordinator writes the brief to a file and runs `python3 -I scripts/agent-route.py run <role> <brief.md>` in the background instead of the Agent tool; the run prints the role's handoff, which ends `Ran on: <provider> / <model> / <effort>`, and keeps its log under `out/logs/`. In Claude Code a `PreToolUse` hook enforces this: it denies an Agent call that does not match the route and names the command. Exit 75 is the provider's usage limit: the run itself then takes every role off that provider in the routing file, back to its pinned agent, and notes it under `bounced` (the page marks those roles and `show` prints `back from <provider>: usage limit`) until the user picks a route for the role again. The coordinator sends the same brief as a plain Agent call and tells the user which role moved and that the provider is out of usage. After a run that failed another way the route stays: send the Agent call with a first prompt line `routing-fallback: <reason>` and say so in the report. The coordinator runs `show` once before the first role invocation of a deliverable, so a routed role's brief is written to a file once instead of being denied and rewritten; a switch made after that is still caught by the hook. Harnesses without the hook run `show` before invoking each role. The route changes who builds, never the scope: the role's instructions, evidence rules and "needs boss" returns are unchanged, and the coordinator views the sheets itself before reporting ([codex skill](../.agents/skills/codex/SKILL.md)).
  - <a id="boss-batches"></a>**Boss batches by build class, one check (Default; user, 20 Nov 2026).** The coordinator dispatches the W5.2 build from the `Build:` line of each shot block ([scene-sheet contract](mark-storyboard-workflow.md#scene-sheet-contract)), not plate by plate: one `boss` invocation for all `hard` shots and one `boss-apply` invocation for all `easy` shots, in parallel when their files do not overlap. A batch over about 15 shots splits by beat range; an [AI09](delivery-workflow.md#agent-invocation) checkpoint still ends a run early. Each batch [builds everything, then returns once](boss-asset-workflow.md#batch-build) with one QA sheet set and one open-item list. `film-apply` then checks every batch in one pass (a frame check of finished shots) and writes one `fixlist.md` round; `boss-apply` applies it in one fix pass under [AI12](#ai12), and a line that needs a new design is the only reason to bring `film` or `boss` back. Target from the batch episodes: Boss at or under $75 and 10 runs for a 28-shot Short (EDU-EP26 $39 in 5 runs, EDU-EP21 $74 in 9); measure with `scripts/usage-report.py` ([CB05](../AGENTS.md#context-budget)). Measured 1–15 Nov 2026: Boss on Opus medium cost $6.52 a run (61 runs, 4.7 runs per branch), on Sonnet medium $1.91 a run (193 runs, 6.2 per branch); Sonnet at `xhigh` cost $7.20 a run, so the effort is not raised.

Independent deliverables (a Short and a Long) may run as parallel invocations. Stages that depend on each other stay in tier order.
